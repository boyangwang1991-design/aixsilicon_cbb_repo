# 详设：impl_tree（PC_IMPL=1）— 折半树/并行前缀优先级网络

## 微架构
- 并行前缀（parallel-prefix）式优先级归约：把"更高优先级段是否已请求"做**折半合并**。
- 思路：为每个 bit i 计算 `hit[i] = req[i]`，以及"低于 i 的段是否有请求"。用分段并行计算
  `block_mask[i] = ~|req[i-1:0]` 的**树状/前缀**形式：
  - 将 N 分为多段，段内链式（线性），段间并行合并段"是否有请求"标志，再向下游段传播。
  - 折半（balanced）版本：递归二分，每层 O(1) 门深，总深度 **O(log N)**。
- 实现采用**递归二分前缀网络**（如 Kogge-Stone 风格简化版或简单折半扫描树）：

  对 LSB 优先（PRIORITY=0）：
  ```
  // 前缀扫描：prefix_or[i] = |req[i:0]
  // grant[i] = req[i] & ~prefix_or[i-1]  （i>0），grant[0]=req[0]
  ```
  `prefix_or` 用折半前缀网络并行计算：区间 [0..i] 的 OR 通过二分树节点传播，
  每段节点宽度 O(N) 每层，深度 O(log N)。

- PRIORITY=1：bit-reverse 输入后套用。
- REQ_TYPE / FAST_GRANT：与 linear 相同的共享外围逻辑（锁存寄存器 + 输出寄存），
  仅仲裁核心（`arb_core`）替换。

## 逻辑深度推导
- 折半前缀网络：每个输出前缀位 O(log N) 逻辑深度 → **O(log N)**。
- 面积：前缀网络每个节点一个 OR，节点总数约 N·log N（简化扫描树则约 2N）。

## 面积/时序驱动要素与理论下界
- **时序**：O(log N) 深度，N 大时（≥16/32）远优于线性链 O(N)。
- **面积**：比 linear 多 O(N log N) 节点（面积中等增大）。
- **理论下界**：优先级选择（one-hot 选择最低有效位）组合深度下界 ~O(log N)
  （需比较前序是否全零），本实现接近该下界。

## PPA 优化点
- 前缀网络分段可复用综合器对 OR 树的平衡（`|` reduction 给工具自由度）。
- N≤8 时综合器自动把前缀网络折叠回近线性最优面积，与 linear 差异极小；
  N≥16 时 tree 的时序优势显现（profile `tree_timing`）。
- 面积优化：仅需输出 N 个 grant 位的前缀（不必算完整 prefix 位宽）——用"前序是否全零"
  的树状传播（每节点 1 bit），避免全位宽前缀数组。

## 生成方式决策
- **SV 手写**：折半前缀用递归 generate（`for(genvar)` 二分合并节点）可简洁表达，
  无数学枚举/复杂调度，符合"SV 优先"决策准则。不使用 Python 生成。
