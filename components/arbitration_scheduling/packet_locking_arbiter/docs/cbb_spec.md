# Packet locking arbiter 规格草案

状态：2026-09-10用户确认规格并授权连续完成设计、验证、验收；YAML为事实源。

## 范围与参数

ARB-010，`aixsilicon:cbb:packet_locking_arbiter:0.1.0`，A2/A3、P1、Standard Loop。
用于已规划的 `axis_mux`（INF-032）和 `stream_interconnect`（INF-036）整包调度；消费者尚未联调。
控制面无 CSR、无数据通路，因此是 CBB。参数：NUM_REQ=1..64（默认4，支持非2次幂），
LOCK_MODE=0/1（默认0，EOP/长度），LEN_W=1..16（默认8）。

## 外部端口

| 端口 | 方向/宽度 | 语义 |
|---|---|---|
| clk / rst_n | 输入，各1位 | 上升沿时钟；异步低有效复位，外部同步释放 |
| req_i | 输入，NUM_REQ位 | 每路当前拍有效，不代表整包连续无空拍 |
| ready_i | 输入，1位 | 被选择数据拍的下游接收能力 |
| eop_i | 输入，NUM_REQ位 | 各路当前拍包尾，仅EOP模式使用 |
| length_i | 输入，NUM_REQ*LEN_W位 | 第i路位段为 [i*LEN_W +: LEN_W]；长度模式的总拍数 |
| grant_o | 输出，NUM_REQ位 | one-hot-or-zero归属选择；锁定时不因req撤回而清零 |

消费者以 `|(grant_o & req_i)` 形成有效信号，并按grant选取数据；
`fire = ready_i && |(grant_o & req_i)` 是唯一接受事件。
这是协议无关控制端口，不新建HWIF协议；实际AXI/Stream绑定由消费者承担。

## 行为

复位期间grant为0，复位后从索引0开始按RR顺序选择有效请求。
首个有授权的上升沿即保留归属，即使下游尚未接受首拍；长度也在此沿采样。
包内空拍、首拍/末拍背压均保持归属，其他源不能插入。
EOP模式仅在选中源末拍被接受时释放，未选中源EOP和空拍EOP无效。
长度模式按接受拍计数（包含首拍），总长度1..2^LEN_W-1；忽略EOP，采样后忽略length变化。
长度0的源暂不参与选择，不阻塞其他合法源。
单拍包在第一次接受时直接完成；完成后下一周期可立即选择下一包，无强制气泡。
RR优先级仅在包完成时推进到原owner+1并回绕，无请求时保留优先级。

所有者必须最终继续发送并结束包，下游必须最终接受，才能保证持续请求者至多等待
NUM_REQ-1个其他完整包；不承诺固定周期上界或按字节公平。
缺失包尾或少发数据会一直占有资源，复位为恢复手段；不提供超时、abort或错误端口。

## 查重、依赖与实现方向

registry已有ARB-010且planned，目录原先不存在，不新增重复条目。
已有round_robin_arbiter的自由模式每次授权就轮转；ACK模式仅在已锁定时处理ACK，
首拍立即ACK不能直接表达本规格的单拍完成语义。故不能直接套用其顶层接口；
详设后采用两路固定优先级仲裁器的稳定组合接口，不依赖既有RR内部状态；
N=1使用直通分支，避免实例化子模块非法参数。依赖RTL未修改，Core构建元数据已修正。
v0.1.0拟采用一个实现方向；EOP/长度是功能模式，不以两种profile冒充不同微架构。
