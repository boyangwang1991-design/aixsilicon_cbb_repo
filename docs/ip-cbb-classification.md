下面这版可作为 **AIXSILICON IP/CBB 分类与入库原则**，用于指导资产规划、开发和仓库整理。

**一、基本定义**

> **CBB 是面向 IP 开发的可复用基础逻辑组件，以核心逻辑能力为边界，重点关注参数化复用、时序行为和逻辑级 PPA。**
>
> **IP 是面向 SoC 或子系统集成的功能组件，以独立集成功能为边界，提供完整的功能行为、接口契约及集成约束。**

分类依据是**组件承担的责任和交付边界**，不以代码量、模块大小或顶层是否直接实例化作为主要判据。

**二、分类判定**

| 判定维度   | CBB                | IP                  |
| ------ | ------------------ | ------------------- |
| 主要使用者  | IP 设计者             | SoC／子系统集成者          |
| 主要用途   | 构建和优化内部逻辑          | 实现独立的系统功能           |
| 功能边界   | 一项基础逻辑能力           | 一项完整集成功能            |
| 接口特点   | 信号、局部握手、简单数据通路     | 完整标准协议或专用系统接口       |
| 协议责任   | 通常不承担完整复杂协议事务      | 按需承担事务、响应、流控及异常处理   |
| 软件管理   | 通常不包含产品级寄存器图       | 按需包含寄存器、描述符、中断及驱动接口 |
| 优化重点   | 关键路径、面积、功耗、扇出、流水结构 | 系统吞吐、延迟、资源配置及整体 PPA |
| 主要交付契约 | 参数、端口、时序和使用约束      | 功能、接口、配置、异常和集成约束    |

**IP 不强制要求 APB/AXI、寄存器、中断或驱动。** 提供独立集成功能的组件，即使没有软件接口，也可以属于 IP。

**三、CBB 入库原则**

1. **核心逻辑明确。** 组件应提供边界清晰的逻辑能力，如存储、仲裁、编码、比较、同步或数据通路处理。
2. **具备实际复用价值。** 应能说明适用的多个 IP 或设计场景；仅服务某个 IP 的内部模块，不因拆分方便而独立入库。
3. **接口尽量简单。** 优先使用信号级、ready/valid、req/ack 等局部接口，避免承载完整系统管理功能。
4. **PPA 特性可描述。** 明确关键路径、延迟、吞吐、流水级数及资源随参数变化的关系；不要求每个 CBB 都有多套实现。
5. **使用约束完整。** 明确参数合法范围、复位行为、边界条件，以及适用的 CDC/RDC、工艺映射或综合约束。
6. **保持合理粒度。** 简单逻辑可以成为 CBB，但应有稳定契约与复用收益；不要求把每个比较器、计数器或组合表达式都封装入库。

**四、IP 入库原则**

1. **具有独立集成用途。** 能在 SoC 架构或集成清单中说明其作用，并作为整体配置、连接和验证。
2. **承担完整功能责任。** 对所支持的功能，明确正常流程、流控、异常、复位及恢复行为。
3. **提供完整接口契约。** 明确协议版本、支持子集、时钟复位、配置参数、性能及集成限制。
4. **管理能力按需配置。** 根据用途提供 CSR、中断、DFX、安全控制、统计和低功耗能力，避免为了满足分类而添加空功能。
5. **复用 CBB，保留专用逻辑。** 通用核心优先引用 CBB；与本 IP 强耦合的内部模块保留在 IP 内部。
6. **整体交付、整体验证。** 使用 CBB 不替代 IP 对接口协同和完整功能的验证责任。

**五、典型边界**

| 组件                             | 分类  | 边界说明                 |
| ------------------------------ | --- | -------------------- |
| FIFO、仲裁器、计数器、优先编码器             | CBB | 通用基础逻辑               |
| CRC、ECC Encoder/Decoder        | CBB | 编码、检测和纠错核心           |
| 同步器、握手 CDC、异步 FIFO             | CBB | 局部跨域机制               |
| 通用 ready/valid 流水切片            | CBB | 缓冲与时序切分              |
| AXI 单通道打拍逻辑                    | IP | 本项目明确归属；仍只负责单通道握手、缓冲和侧带保持 |
| 完整 AXI Register Slice／TPI      | IP  | 提供完整 AXI 接口集成契约      |
| APB Register Bridge            | IP  | 负责上下游 APB 阶段、等待及响应协调 |
| APB／AXI／AHB CDC Bridge         | IP  | 完整总线事务跨域             |
| APB MUX／DEMUX、AXI Interconnect | IP  | 协议级选择、路由与响应          |
| 地址匹配、权限比较核心                    | CBB | 输出匹配或授权结果            |
| AXI MPU、安全 APB DEMUX           | IP  | 访问拦截、拒绝响应及权限管理       |
| SRAM／ROM 工艺宏基础封装               | CBB | 统一宏端口、时序和工艺差异        |
| SRAM Controller                | IP  | 访问组织、仲裁、ECC及错误管理     |
| 锁步对齐、比较和局部故障指示                 | CBB | 核心安全机制               |
| 锁步管理控制器                        | IP  | 主影协同、复位、诊断与系统故障管理    |
| Scoreboard、依赖跟踪核心              | CBB | 具有独立、可复用的状态管理契约      |
| Scheduler                      | IP  | 任务入队、依赖管理、派发和完成处理    |
| GPIO、SPI、Watchdog、DMA          | IP  | 完整外围或系统功能            |

**包含协议信号不自动决定分类，与 PPA 强相关也不自动意味着属于 CBB。** 应看组件是否承担完整协议及集成功能。

**六、实现方式与分类分离**

| 维度   | 可选形式                         | 含义            |
| ---- | ---------------------------- | ------------- |
| 资产分类 | IP／CBB                       | 交付什么能力、承担什么责任 |
| 实现方式 | Parameterized／Generator／固定实现 | 如何配置和生成硬件     |
| 封装形式 | 原生逻辑／Wrapper／组合组件            | 如何组织实现与外部依赖   |

例如，ECC Generator 可以属于 CBB，多端口 SRAM Controller Generator 属于 IP。**不能仅因为使用 Generator，就将组件归为 IP。**

优先使用参数化表达稳定结构中的位宽、深度、路数和可选功能；当配置涉及复杂拓扑、非规则连接或多组件组装时，再采用 Generator。

**七、去重与仓库管理**

* **一项核心实现只维护一份。** IP 可通过依赖引用 CBB，避免复制源码形成两套实现。
* **同一功能家族优先统一。** 仅参数、流水深度或实现结构不同的组件，优先作为同一资产的配置或实现变体；合并前必须确认功能契约。
* **不为分类增加空封装。** 只有增加了实际协议或集成功能，才需要形成独立 IP。
* **第三方混合库按依赖管理。** primitive 包、协议组件集合、测试库和常量包，不直接整体认定为一个 IP/CBB。
* **示例与方法不计入产品主清单。** 模板、参考组合、PPA 配方和通用开发方法应与正式硬件资产区分。
* **仓库维护资产及其交付件。** 包括源码、规格、验证材料、状态、版本、依赖和 FuseSoC 信息；通用开发方法由 Skill 维护，Skill 为具体资产生成的交付件随资产保存。
* **编号保持稳定。** 不因排序或清单精简重新编号；迁移、合并、退役保留原编号映射，不复用退役编号。
* **规划与实现状态分离。** 计划支持、开源上游支持或文档已完成，不等于本仓库已实现并验证。

**八、核心资产保留与精简**

核心资产优先满足当前项目需求、跨项目复用、基础依赖和明确的工程收益。

非核心候选可退出主清单，但应遵循：

* 不按 P2/P3 优先级一刀切删除。
* 已实现或被其他资产引用的组件，先检查依赖再处理。
* 优先精简缺少明确需求的专用算法、远期协议、重复规划和大型组合候选。
* 移除规划条目保留原因与恢复记录；清单移除不等于可以直接删除源码。
